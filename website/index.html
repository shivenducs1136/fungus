What gets pressed into the record, and where it resurfaces.

a

Working notes, kept

Whatever an agent or engineer figures out mid-session — the reason for the odd branch, the migration that never got documented — gets written to the file it concerns, not lost to a closed tab.

b

Rooted to Git History

Context spreads along real dependencies. By linking the deep knowledge document to a context hash (ctx-xxxx) in the Git Commit Message, the information is bound to the exact point in time the codebase changed.

c

Any agent can read it

Served over MCP. Claude, Cursor, or your own scripts all pull from the same accumulated record — nothing re-explained twice. No vector databases, embeddings, or RAG needed. O(1) retrieval.

d

The codebase speaks for itself

When you ask "Why is this implemented this way?", Fungus performs a git blame, retrieves the commit, extracts the key, and serves the rationale perfectly.

Here's why these operators were added:

1. Tilda ( ~ ) operator ref: TPR-2093

  • Added by: Deva Harsha BT for the Custom PDF Engine.
  • Purpose: String position calculation — calculates position accurately for each word in a string.
  • Implementation: a*-1 + b*-1 negates both operands and sums them.

2. Power ( ^ ) operator ref: TPR-3001

  • Added by: Yashas and Yashwanth for the UI team.
  • Purpose: Exponential zone calculations in the UI.
  • Implementation: a ** b (standard Python exponentiation).

Both were domain-specific requirements: the tilda operator supports the PDF engine's text positioning logic. They're not general-purpose calculator features—they're specialized for Tally Prime's specific use cases.
